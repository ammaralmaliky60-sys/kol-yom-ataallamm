# دليل تطوير كل يوم أتعلم

هذا الدليل لتشغيل المشروع وتعديل واجهته وإضافة المحتوى ونشره. دليل استخدام المدرسة وخطة التعلم في [دليل المتعلم](LEARNER_GUIDE.md).

## 1. التشغيل المحلي

ثبت Node.js 20 أو أحدث، ثم افتح الطرفية داخل مجلد المشروع:

```bash
node server.mjs
```

افتح `http://localhost:3000`. لا توجد حزم تشغيل خارجية ولا حاجة لـ npm install لتشغيل التطبيق. لتغيير المنفذ: `PORT=8080 node server.mjs` على macOS وLinux. على PowerShell استخدم `$env:PORT=8080` ثم أمر التشغيل.

لا تفتح index.html مباشرة بصيغة file://؛ وحدات JavaScript وservice worker تحتاج خادماً. localhost على هاتفك يعني الهاتف نفسه؛ تشغيل PWA والميكروفون على iPhone يحتاج رابط HTTPS يمكن للهاتف الوصول إليه.

## 3. أضف درساً حقيقياً

أضف كائناً إلى مصفوفة المسار المناسب. مصفوفة الكمبيوتر تسمى computerLessons، والثقافة cultureLessons. ملف الإنجليزية يستخدم دالة داخلية لتجميع الدروس؛ اتبع بنيته الحالية عند إضافة درس. مثال مخطط موحد:

```js
{
  id: 'pc-041',
  track: 'computer',
  level: 'متقدم',
  unit: 'العمل الرقمي',
  title: 'نسخة احتياطية قابلة للاستعادة',
  description: 'تأكد من قدرتك على استعادة ملفاتك من نسخة منفصلة.',
  minutes: 10,
  sections: [
    {title: 'النسخ والاستعادة', body: 'النسخة الاحتياطية نسخة منفصلة يمكن استعادة الملفات منها عند فقد الأصل. اختبر استعادة ملف غير حساس إلى مجلد جديد قبل الاعتماد على الخطة.'}
  ],
  practice: 'انسخ ملف تدريب إلى وسيط منفصل، ثم استعده إلى مجلد آخر وتحقق من فتحه.',
  visual: 'files',
  questions: [
    {type: 'choice', prompt: 'كيف تتحقق من فائدة النسخة الاحتياطية؟',
     options: ['اختبار استعادة ملف وفتحه', 'تغيير لون المجلد', 'إخفاء الملف الأصلي'],
     answer: 'اختبار استعادة ملف وفتحه',
     explanation: 'اختبار الاستعادة يثبت أنك تستطيع استخدام البيانات المنسوخة.'}
  ]
}
```

اجعل كل درس متكاملاً: شرح مبتدئ واضح، أمثلة، تطبيق، وعدة أسئلة تختبر الفهم. استخدم نصاً عادياً دون HTML في المحتوى. حافظ على المعرفات القديمة بعد النشر كي يبقى التقدم مرتبطاً بالدروس. ترتيب المصفوفة هو ترتيب فتح الدروس؛ لا تعيد ترتيبه بلا مراجعة للمتطلبات السابقة.

في درس الإنجليزية أضف vocabulary: عناصر word وmeaning وpronunciation وexample وtranslation. النطق العربي تقريبي. وفر ثلاث مفردات على الأقل عند استخدام دالة تجميع المحتوى الحالية. أنواع الأسئلة: choice وinput وorder وboolean وlistening. الإجابة answer نص، والخيارات options نصوص. أضف explanation لكل سؤال. يدعم التصحيح acceptedAnswers عند وجود بدائل صحيحة معروفة.

في order ضع الكلمات في options، والجملة الصحيحة في answer. الكلمات المكررة مسموحة وتظهر كبطاقات مستقلة. في listening أضف audio بالنص الإنجليزي الذي ينطقه المتصفح. لا تجعل الصوت في حقل السؤال هو الإجابة المكشوفة.

أضف sourceLabel وsourceUrl للقراءات المرجعية، وراجع المصدر والمعلومة قبل النشر. لا تضع محتوى مؤقتاً أو إجابات عشوائية، ولا تدّعِ اعتماداً تعليمياً غير متوفر.

## 4. قواعد التقدم والنتائج

اجتياز الدرس يتطلب 75%. لا يفتح الدرس التالي بالقراءة وحدها، ولا توجد حصص يومية. أول اجتياز يمنح 50 نقطة، والإعادة تحفظ أفضل درجة دون تكرار المكافأة. التطبيق العملي موصى به؛ زر الاختبار يفتح مباشرة. لا يوجد زر تحقق إضافي: الاختيارات تصحح فور التحديد، وترتيب الكلمات عند اكتماله، والكتابة عند Enter أو مغادرة الحقل. يحمي quizFeedback من احتساب الإجابة أكثر من مرة.

تحديد المستوى تدريجي. لكل مستوى سؤالان من كل درس، ويلزم 90% وصواب سؤال واحد على الأقل في كل موضوع. النتيجة تسمح بتجاوز موضوعات المستوى المقيم؛ ليست شهادة CEFR أو تقييماً بشرياً شاملاً للكتابة والتحدث.

## 5. التخزين والنسخ الاحتياطي

المفتاح المحلي learn-everyday-v1 يحتوي version وname وcompleted وfavorites وhistory وweakWords وxp وactivity وreview وplacementPassed وgoal. عند تغيير المخطط أضف ترحيلاً مدروساً؛ لا تمسح بيانات المتعلمين لمجرد تغيير نسخة التطبيق. لا تضع بيانات أشخاص أو نتائج تصدير حقيقية داخل المستودع.

يمكن لاحقاً استبدال الحفظ بواجهة API وقاعدة بيانات، مع حسابات وصلاحيات ومزامنة ومعالجة التعارضات. أبقِ معرّفات الدروس ثابتة. لا تضع مفاتيح سرية في JavaScript أو ملفات dist؛ كل ما يصل إلى المتصفح يمكن قراءته.

## 6. الصوت والتوافق

speechSynthesis يعتمد أصوات الجهاز. SpeechRecognition أو webkitSpeechRecognition قد لا يتوفر أو يحتاج اتصالاً وإذن الميكروفون. MediaRecorder يسجل الصوت لإعادة تشغيله، ويغلق مسارات الميكروفون عند الانتهاء أو مغادرة التدريب. راعِ هذا التنظيف عند تعديل الصفحات.

compareSpeech يقارن النص المعروف بالنص المستهدف. لا تستخدم نتيجته بوصفها درجة مخارج حروف أو جودة لكنة. اختبر Safari وiPhone فعلياً قبل وصف إصدار جديد بأنه معتمد عليهما؛ المحاكاة في Chromium لا تكفي لإثبات سلوك Safari.

## 7. الفحص قبل النشر

```bash
npm run build
npm test
```

الأمر الأول يفحص JavaScript وملفات PWA ومعرفات الدروس والحقول والأجوبة، ولا ينشئ حزمة لأن المشروع ثابت. الثاني يشغل اختبارات المحرك والحفظ والصوت.

للاختبارات التفاعلية الاختيارية:

```bash
npm install --no-save playwright
npx playwright install chromium
node server.mjs
```

وفي طرفية أخرى: `node tests/browser.mjs`. قد تحتاج تعيين BROWSER_PATH لمسار Chromium المثبت. لا يلزم Playwright للمستخدم النهائي. يشغّل الاختبار متصفحاً منفصلاً ويستخدم بيانات تعلم اختبارية، ويكتب التقرير والصور إلى qa/ المستبعد من Git.

اختبر يدوياً: أول درس، الفشل ثم النجاح، الدرجة بعد التحديث، قفل التالي، البحث، المفضلة، التسجيل وإيقافه، التصدير والاستعادة، الهاتف، والعمل دون اتصال بعد أول تنزيل. راجع docs/TESTING.md لحدود التحقق الحالي.

## 8. النشر وGitHub Pages

انشر محتويات dist إلى استضافة ثابتة تدعم HTTPS. جميع الروابط نسبية لتعمل أيضاً تحت مسار مشروع. لا تنشر المجلد الأب كصفحة HTML رئيسية؛ index.html موجود داخل dist.

لـ GitHub Pages: من Settings → Pages اختر GitHub Actions. يحتوي المشروع سير عمل deploy-pages.yml للتشغيل اليدوي workflow_dispatch. افتح Actions ثم Deploy educational PWA to GitHub Pages ثم Run workflow بعد تمكين Pages. قد تتطلب Pages خطة تدعم المستودعات الخاصة. لا تغيّر خصوصية المستودع تلقائياً؛ اختر استضافة تناسب متطلباتك إذا أردت إبقاء الشفرة خاصة.

سير العمل يشغل الاختبارات وفحص المحتوى ثم يرفع dist، ولا يستخدم أسراراً شخصية؛ يحتاج أذونات Pages وOIDC القياسية. حفظ المشروع في GitHub وحده لا يعني أن GitHub Pages أصبح منشوراً.

## 9. تحديث PWA دون فقد التقدم

عند تعديل الملفات ارفع رقم CACHE في dist/sw.js وأضف أي ملف جديد إلى FILES. اختبر أن الزيارة الأولى تخزن الملفات، وأن إعادة التحميل دون إنترنت تفتح الدروس. لا تخزن طلبات خدمات خارجية أو أسراراً ضمن قائمة التطبيق.

التحديث الجديد قد ينتظر إغلاق نوافذ التطبيق القديمة. أخبر المتعلم بإعادة تحميل الصفحة أو إغلاق التطبيق وفتحه؛ لا تطلب مسح بيانات الموقع قبل تصدير التقدم. التخزين المحلي منفصل عن مخبأ الملفات، وتغيير رقم المخبأ لا يمسح النتائج.

## 10. مسار تطوير مقترح

ابدأ بإضافة درس واحد عالي الجودة، وشغّل الفحوص، واختبره، ثم زد الوحدات تدريجياً. بعد استقرار المحتوى أضف فهرسة بحث للكتب الكبيرة، ومراجعة متباعدة للكلمات، ثم حسابات ومزامنة عند الحاجة. راجع المحتوى علمياً ولغوياً مع مختصين، وأضف تقييماً بشرياً للتحدث والكتابة إذا أردت قياس إتقان أعمق.
